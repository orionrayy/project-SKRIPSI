# Phase Map P0–P9

| Phase | Name | Required outcome | Dependency / gate |
|---|---|---|---|
| P0 | Research Charter & Integrity | Charter, integrity/authorship/privacy governance, risks, approval matrix and decision record | Human approval `APR-P0-001` recorded for scoped baseline |
| P1 | Cross-Domain Thesis Corpus | At least 50 verified eligible S1 theses, ten primary domains × five, traceable records, schema/CSV/source ledger/QA | P0 approval; P1 acceptance is a separate human decision |
| P2 | Thesis Extraction & Coding | Codebook, evidence-located extraction, coverage/missingness, coding QA/adjudication | P1 COMPLETE_AND_APPROVED + separate P2 start authorization |
| P3 | Cross-Domain Synthesis | Evidence-linked patterns, contradictions, confidence, universal/domain/method/institution distinctions | P2 COMPLETE_AND_APPROVED + separate P3 authorization |
| P4 | University Compliance | Versioned official guideline registry and testable compliance profiles | P3 accepted + authorization; institution-specific sources required |
| P5 | Methodology & Data Validity | Discipline-appropriate coherence and data-provenance validation | P4 accepted + authorization |
| P6 | Evidence, Citation & Ethics | Claim-source traceability, bibliographic checks, rights/ethics controls | P5 accepted + authorization |
| P7 | Semantic & Humanized Writing | Natural academic language and reasoning QA without detector evasion | P6 accepted + authorization |
| P8 | Repository & Execution Engineering | Production architecture, isolation, workflows, tests, integration and reproducibility | P7 accepted + authorization |
| P9 | Red-Team & Final Prompt Compilation | Adversarial validation, cross-domain acceptance, final prompt/configuration | P8 accepted + authorization |

Do not treat this phase map as an implementation report. A future phase requires its own deliverables, validation, acceptance and authorization.
